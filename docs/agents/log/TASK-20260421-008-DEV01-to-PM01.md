# TASK-20260421-008 DEV-01 Completion Report

## Data model summary

| Layer | Field | Meaning |
|-------|--------|---------|
| `SimpleDatabase` | `nurses` (+ `layoutName` on rows) | **Active / current shift** nurse cards for each layout |
| `SimpleDatabase` | `nurses_oncoming` (+ `layoutName`) | **Oncoming draft** nurse cards (isolated until activation) |
| UI | `nurses` state in `unit-view-client.tsx` | Drives PatientGrid + main Spectralink table |
| UI | `oncomingNurses` state | Fed only to **Shift Maker**; drag/drops update assignments **without** changing `patient.assignedNurse` |

**Activation:** `activateOncomingShift(layoutName)` replaces persisted `nurses` for that layout with the current `nurses_oncoming` snapshot, then clears `nurses_oncoming` for that layout. React state then reloads active nurses and runs `syncPatientsAssignedNurseFromNurses` so census `assignedNurse` matches the promoted slots.

## Before / after behavior

- **Before:** Shift Maker used the same `nurses` state as the live map; saving assignments and drag/drop affected the active board.
- **After:** Opening “Oncoming shift” seeds an oncoming draft (copy of active if empty). Shift Maker reads/writes **only** `oncomingNurses`. Main map handlers still use **only** `nurses`. “Activate oncoming shift” performs a single swap (DB + state + patient sync). Assignment snapshot from the header uses oncoming nurses when that flow is active.
