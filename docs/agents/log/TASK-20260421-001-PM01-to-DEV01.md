## Context

Renderer `npx tsc --noEmit` fails with multiple errors in `src/lib/database-simple.ts`: filters and saves assume `layoutName` on `Patient`, `Nurse`, and `PatientCareTech`, while the public domain types in `src/types/` do not declare that field. `getUserPreferences()` is typed to return `UserPreferences` but implementation returns a plain string map missing required keys per type.

## Objective

Align the **persistence layer types** with how `SimpleDatabase` actually stores per-layout rows (or refactor the DB layer to use explicit DTO types) so **all `database-simple.ts` TypeScript errors are resolved** without breaking runtime behavior.

## Scope (in repo)

- `renderer/src/lib/database-simple.ts`
- `renderer/src/types/patient.ts` (and related types as needed)
- `renderer/src/types/nurse.ts` (and related types as needed)
- Any minimal touch points required for consistency (e.g. services that construct rows)

## Out of scope

- Feature work, UI changes, performance refactors unrelated to these type errors.
- Rewriting persistence to a new storage backend.

## Acceptance criteria

1. `npx tsc --noEmit` run from `renderer/` produces **zero errors** whose file path is `src/lib/database-simple.ts`.
2. No regression in behavior: existing layouts still load/save; `layoutName` semantics remain correct for multi-layout storage.
3. If you introduce a dedicated `StoredPatient` / `StoredNurse` type, document in code comments **briefly** why it exists (one sentence per type is enough).
