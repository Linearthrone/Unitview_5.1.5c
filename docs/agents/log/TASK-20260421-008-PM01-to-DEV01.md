## User requirement (authoritative)

1. On active shift board, user can add/remove a nurse on an existing active nurse card.
2. On upcoming (oncoming) shift board, edits must NOT affect current active shift assignments.
3. User can add/remove nurses and nurse cards in upcoming shift prep.
4. Upcoming shift prep must persist until user activates it.
5. On activation:
   - current shift staff assignments end,
   - current shift cards are removed,
   - prepped upcoming shift cards become current active shift cards.

## Objective

Implement true two-board shift state with isolation + activation promotion.

## Required implementation

- Introduce explicit shift state separation:
  - `currentShift` data
  - `oncomingShift` draft data
- Ensure all edits in Shift Maker / upcoming board write only to `oncomingShift`.
- Active board continues to read/write only `currentShift`.
- Add card lifecycle operations for both contexts:
  - add nurse card
  - remove nurse card
  - assign/unassign nurse on card
- Add `Activate Oncoming Shift` workflow that atomically:
  1) archives/ends current assignments,
  2) replaces current cards+assignments with oncoming draft,
  3) clears or resets oncoming draft for next cycle.
- Persist both states in storage so refresh/reload retains prep data.
